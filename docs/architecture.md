# 구조

웹 클라이언트는 Spring 서버의 `/api`만 호출합니다. AI 서버(검색·답변)는 직접 호출하지 않고 서버를 거칩니다. 로컬에서는 Vite 개발 서버가 `/api`를 `http://localhost:8080`으로 프록시합니다.

## Feature-Sliced Design

폴더는 [Feature-Sliced Design](https://feature-sliced.design/kr/)을 따릅니다. 위 레이어는 아래 레이어만 가져올 수 있고, 같은 레이어의 다른 슬라이스는 가져올 수 없습니다.

| 레이어     | 역할                                    | 현재 슬라이스                                                                                                                                                                          |
| ---------- | --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app`      | 진입점, 라우터, 전역 스타일             | 슬라이스 없음 (`routes`, `model`, `styles`)                                                                                                                                            |
| `pages`    | 라우트 하나당 화면 하나                 | `login`, `workspace`, `admin-documents`, `admin-document-detail`                                                                                                                       |
| `widgets`  | 독립적인 큰 화면 블록                   | `editor-area`, `chat-panel`, `document-graph`, `document-viewer`, `sidebar`, `admin-document-table`                                                                                    |
| `features` | 사용자 동작 단위 기능                   | `auth`, `ask-question`, `document-tabs`, `filter-documents`, `conversation-history`, `create-source`, `upload-documents`, `edit-document-access`, `revise-document`, `delete-document` |
| `entities` | 문서, 청크, 사용자 같은 업무 개념과 API | `user`, `document`, `department`, `answer`, `conversation`, `evidence`, `source`                                                                                                       |
| `shared`   | 업무 지식 없는 공통 코드                | 슬라이스 없음 (`api`, `config`, `ui`, `testing`)                                                                                                                                       |

```
src/
  app/
    routes/router.tsx       라우트 정의 (/login, 인증이 필요한 /, 관리자용 /admin/documents[/:id])
    routes/AuthGuard.tsx    토큰이 없거나 만료되면 로그인으로 이동
    routes/AdminGuard.tsx   관리자 역할이 아니면 /로 이동 (화면 편의용)
    model/resetOnLogout.ts  로그아웃·만료 시 대화와 탭 상태 초기화
    styles/index.css        Tailwind와 전역 스타일
    App.tsx                 QueryClient·Router 연결
  pages/
    login/                  로그인 화면
    workspace/              메인 화면 (그래프·문서 탭 + 채팅)
    admin-documents/        문서 관리 목록 (소스 선택·추가, 업로드, URL 쿼리 필터)
    admin-document-detail/  문서 관리 상세 (처리 상태, 기본 정보, 권한, 버전 이력, 내용 편집·개정·삭제)
  widgets/
    editor-area/            그래프·문서 탭 영역 (그래프와 문서 뷰어는 페이지가 넣어 줌)
    chat-panel/             채팅 패널 (근거를 누르면 문서 탭 열기)
    document-graph/         Sigma.js 문서 그래프 (lib: 그래프 구성·배치·색)
    document-viewer/        문서 상세 정보, PDF·Markdown 원문 뷰어와 원문 안 근거 하이라이트
    sidebar/                왼쪽 네비게이션 (새 질문, 최근 대화 목록, 프로필)
    admin-document-table/   관리자 문서 목록 필터 + 표 + 페이지 이동
  features/
    auth/                   로그인·로그아웃
    ask-question/           질문 보내기, 대화 상태, 근거 강조 대상
    document-tabs/          탭 열기·전환·닫기
    filter-documents/       문서 유형·확장자·기간·부서·작성자·소스 종류 필터 상태
    conversation-history/   과거 대화를 메시지 목록으로 재구성해서 열기
    create-source/          소스 추가 모달
    upload-documents/       업로드 모달 (lib: 경로 만들기·미리 거르기·묶기, model: 묶음 순차 전송)
    edit-document-access/   열람 권한 보기·수정
    edit-document-text/     md·txt 내용 편집, 저장하면 새 버전 (PDF는 서버 지원 대기). 개발 서버에서는 메모리에만 저장하고 수정 문서를 참조하는 간선을 빨갛게 표시하며, 수정 제안을 수락하면 함께 인용한 문서와의 충돌만 화면에서 지우고, 새로고침하면 돌아감. 서버 저장은 `VITE_EDIT_PROPOSAL_SAVE=true`일 때만 하며 재적재 연결 뒤에 켬
    revise-document/        파일 1개로 새 버전 만들기
    delete-document/        소프트 삭제 확인
  entities/
    user/                   사용자 타입과 GET /api/users/me
    document/               문서 타입과 목록·상세·다운로드·처리 상태 API, 관리자 API(/api/admin/documents)
    source/                 소스 타입과 관리자 소스 API(/api/admin/sources)
    department/             부서 타입과 GET /api/departments
    answer/                 질문 API(POST /api/conversations/messages)와 답변 타입
    conversation/           대화 목록·상세·삭제 API (GET·DELETE /api/conversations[/{id}])
    evidence/               근거 조회 API(GET /api/evidence/{chunkId})와 원문 안 근거 위치 찾기
  shared/
    api/                    HTTP 클라이언트, 응답 봉투, 토큰, 오류 문구, queryClient
    config/                 환경 변수, 업로드 한도 상수
    ui/                     모달·카드·버튼 스타일 같은 공통 UI
    testing/                테스트 전용 가짜 서버 도우미
```

슬라이스 안은 목적별 세그먼트(`ui`, `model`, `api`, `lib`, `config`)로 나누고, 바깥에는 `index.ts`로 공개할 것만 내보냅니다. `npm run lint`가 Steiger로 이 규칙을 검사합니다.

## 메인 화면

- 로그인하면 토큰을 세션 스토리지에 보관하고 `GET /api/users/me`로 사용자 정보를 받습니다. 토큰이 없거나 401을 받으면 토큰을 지우고 로그인 화면으로 보냅니다.
- 왼쪽 네비게이션(사이드바)은 항상 보입니다. 대화가 없으면("홈") 가운데 큰 입력창을 보여주고, 첫 질문을 보내면 그래프·문서 탭 + 채팅 레이아웃("답변")으로 바뀝니다. 둘 다 같은 라우트(`/`)의 `WorkspacePage` 안에서 `messages.length`로 전환하며, 별도 라우트를 두지 않습니다.
- 왼쪽 탭 영역은 고정된 그래프 탭과, 연 순서대로 쌓이는 문서 탭으로 구성합니다. 같은 문서를 다시 열면 기존 탭으로 이동합니다. 탭이 영역 폭을 넘으면 가로로 스크롤하고, 그래프 탭은 왼쪽에 고정되며, 새로 열거나 고른 탭은 보이는 위치로 스크롤합니다.
- 필터를 고르면 버튼 이름 뒤에 고른 항목 수를 "문서 유형 (1)"처럼 붙입니다. 화면은 그래프와 채팅 사이, 문서 미리보기와 채팅 사이의 손잡이를 끌어 크기를 바꿀 수 있고, 글자가 잘리지 않게 그래프 360px, 채팅 340px, 미리보기 180px, 미리보기 아래 채팅 240px보다 작아지지 않습니다. 답변을 기다리는 동안 입력창 위에 따로 띄우던 "Trace가 답변을 생성 중…" 줄은 대화 목록의 대기 표시와 겹쳐 없앴습니다.
- 사이드바 로고와 "New Chat"은 대화를 비우고 그래프 탭, 빈 채팅, 닫힌 미리보기의 첫 메인 화면으로 갑니다. 답변을 기다리는 중이면 화면만 옮깁니다.
- 첫 질문 전에도 빈 홈 화면 대신 노드만 있는 그래프와 채팅을 바로 보여 줍니다. 채팅이 비어 있으면 예시 질문 15개를 한 글자씩 썼다가 지우며 차례로 보여 줍니다(`features/ask-question/lib`). 움직임 줄이기 설정이면 첫 예시만 그대로 보여 줍니다.
- 필터 버튼의 패널은 열 때 버튼 위아래 남은 공간을 재서 화면 밖으로 잘리지 않는 쪽으로 펼치고, 남은 높이를 넘으면 패널 안에서 스크롤합니다. 바깥을 누르거나 Esc를 누르면 닫혀 두 패널이 겹치지 않습니다. 홈 화면의 "필터" 패널은 세로 공간을 줄이려고 두 열(유형·확장자 / 기간·부서·작성자)로 보여줍니다.
- 그래프 탭을 열면 노드가 약 1초 동안 하나씩 작게 나타나 살짝 튀었다가 제 크기로 돌아옵니다(`lib/nodePop`). 선은 양 끝 노드가 다 나온 뒤에 보입니다.
- 그래프 탭은 볼 수 있는 모든 문서를 노드로 한꺼번에 보여주고 문서 유형별로 색을 나눕니다. 평소에는 선을 그리지 않습니다. 질문하면 답변이 인용한 문서와 나머지 출처 문서를 순서대로 잇습니다. 충돌 쌍만 남기는 것은 질문이 충돌이나 불일치를 물을 때뿐이고, 답변에 차이가 언급됐다고 바뀌지 않습니다. 그래프를 다시 그릴 때마다(새 답변, 필터 변경, 그래프 탭을 다시 열 때) 근거 1번 노드부터 다음 노드까지 선이 차례로(선 하나에 0.25초) 그어지는 애니메이션을 보여 주고, 끝나면 실제 선으로 바뀝니다. 움직임 줄이기를 설정한 사용자에게는 건너뜁니다. 실제 관계(참조, 충돌, 주제)가 있는 쌍은 그 선을, 없는 쌍은 "답변 근거" 선을 그립니다. 근거끼리의 다른 실제 관계 선도 보이고, 근거와 이웃 문서 사이 선은 그리지 않습니다. 노드에 마우스를 올리면 그 노드의 선이 보입니다. 노드를 누르면 그 노드의 선이 모두 보이고 다른 선은 숨깁니다. 문서는 오른쪽 채팅 위에 미리보기로 뜹니다. 미리보기에서 탭으로 열 수 있고, 빈 곳을 누르거나 미리보기를 닫으면 기본 보기로 돌아갑니다. 서버가 권한 범위의 문서만 주므로 권한 없는 문서는 나타나지 않습니다.
- 문서 탭은 문서 정보와 버전·처리 상태를 보여주고, 확장자에 따라 PDF(`react-pdf`)와 Markdown(`react-markdown`) 원문을 표시합니다. 처리 중인 문서는 5초마다 상태를 다시 확인해 완료되면 자동으로 갱신합니다.
- 원문 파일은 `GET /api/documents/{id}/download`(관리 화면은 `/api/admin/documents/{id}/download`)에서 받습니다. 서버(`Trace-Server` PR #75)가 S3 presigned URL 대신 Spring으로 파일을 스트리밍하고 인증 헤더를 요구하므로, 브라우저가 주소를 직접 열지 않고 `@/shared/api`의 `requestBlob`으로 받은 파일을 그리거나 저장합니다. `download-url` API는 쓰지 않습니다. 같은 문서·버전의 파일은 내용이 바뀌지 않아 버전 번호를 키로 캐시하고, 다운로드 버튼은 미리보기로 이미 받은 파일을 그대로 저장합니다. 새 창으로 열지 않고 파일로만 내려받으므로 파일 내용이 이 사이트 출처에서 실행되지 않습니다.
- 오른쪽 채팅 패널에서 질문하면 서버의 질문 API로 보냅니다. 단건 응답이고 최대 70초까지 걸릴 수 있어 대기 표시를 보여줍니다. 대화는 메신저처럼 그립니다. 내 질문은 오른쪽 밝은 말풍선, 답변·오류는 왼쪽에 Trace 프로필(사이드바와 같은 로고, `shared/brand`)과 이름을 붙인 어두운 말풍선이고, 상대 말풍선이 연달아 오면 첫 말풍선에만 프로필을 붙입니다. 말풍선 옆에는 보낸 시각을 표시합니다(새 메시지는 화면에서 만든 시각, 과거 대화는 서버의 `createdAt`). 답변을 기다리는 동안에는 상대 말풍선 자리에 점 3개 "입력 중" 표시와 경과 시간을, 서버가 진행 단계를 알려주지 않아 단계별 문구는 두지 않았고, 질문 요청을 중간에 끊는 API도 없어 생성 취소 버튼은 두지 않았습니다. 첫 질문은 새 대화를 만들고, 이후 질문은 같은 대화에 이어서 보냅니다. 답변을 기다리는 동안 새 대화를 시작하거나 다른 대화를 열거나 로그아웃하면, 늦게 도착한 답변과 오류는 바뀐 화면에 붙이지 않고 버립니다.
- 답변 문장은 LLM이 만든 Markdown(제목, 굵게, 목록, 표, 코드 등)을 `react-markdown`과 `remark-gfm`으로 서식에 맞춰 보여줍니다(`features/ask-question/ui/AnswerMarkdown.tsx`). 원시 HTML은 렌더링하지 않고, 답변에 섞인 외부 URL을 브라우저가 자동으로 요청하지 않도록 이미지도 표시하지 않습니다. 링크는 새 탭(`noopener noreferrer`)으로 엽니다.
- 답변 아래 근거는 근거 문서와 핵심 인용을 한 카드로 묶어 보여줍니다. 카드 한 장에 번호·문서 제목·조항(청크 첫 줄이 Markdown 제목이나 "제N조"일 때만)과 그 근거에서 그대로 발췌한 인용 문장을 표시합니다. 인용은 같은 청크의 근거, 없으면 같은 문서의 첫 근거 카드에 붙이고, 근거 목록에 없는 문서의 인용은 카드를 따로 만듭니다(`features/ask-question/lib/evidenceCards.ts`). 시안의 버전 표시(`v2`)는 `AnswerSource`에 버전 번호가 없어(버전 ID만 있음) 넣지 않았습니다.
- 답변의 근거를 누르면 해당 문서 탭이 열리고, 원문(Markdown 본문, PDF 텍스트 레이어) 안에서 근거를 직접 칠한 뒤 그 위치로 스크롤합니다. AI가 그 문서에서 뽑은 인용(`evidence[].quote`)은 누른 청크가 아니라 같은 문서의 다른 청크에서 나왔어도 칠하고, 키워드는 누른 근거 청크 구간 안의 것만 칠합니다. 청크 전체는 칠하지 않으며, 칠할 문구가 없으면 근거 청크 위치로 이동만 합니다. 원문 위에는 근거 상태(버전, 쪽, 찾지 못함, 오류)와 "근거로 이동"·닫기만 있는 한 줄 바를 둡니다. 가장 최근 답변의 근거 문서는 그래프에서 강조되고, 새 질문을 하면 이전 강조를 지웁니다.
- 실패한 요청은 서버 오류 코드에 맞는 한국어 문구로 화면에 표시합니다.

## 문서 관리 화면

관리자(`DOC_ADMIN`·`SYSTEM_ADMIN`)는 사이드바의 "문서 관리"로 `/admin/documents`에 들어가 소스 추가, 폴더·파일 업로드, 권한 수정, 개정, 삭제를 합니다. 화면 구성, 서버 동작 확인 결과, 남은 결정은 [문서 관리 화면](admin-documents.md)에 있습니다.

- **토큰 보관**: 세션 스토리지. 새로고침해도 로그인이 유지되고 탭을 닫으면 지워집니다. 서버 토큰은 1시간 후 만료되고 갱신 토큰이 없어, 만료되면 다시 로그인해야 합니다. 갱신 토큰은 서버 정책이 정해지면 반영합니다.
- **답변 방식**: 서버 결정을 따릅니다. 지금 서버는 SSE가 아닌 단건 응답이므로 스트리밍을 쓰지 않습니다.
- **그래프**: 서버 API(#22)가 머지되어 `GET /api/graph`의 실제 `edges`로 연결선을 그립니다(`entities/graph`). `REFERENCES`(참조)는 파랑, `CONFLICTS`(충돌)는 빨간 선과 `경고! 내용 충돌 · {항목}` 문구로 구분합니다. 그래프가 무방향·쌍마다 선 하나만 허용하는 구조라, 같은 문서 쌍에 참조·충돌이 둘 다 있으면 충돌 선이 우선합니다. 선을 누르면 충돌 값과 경고 내용을 패널로 보여 줍니다. `warnings`의 `SECURITY_RISK`는 빨간 경고로 표시하고, `CONTENT_CHECK`는 적재 순서로 붙는 조건이 고쳐질 때까지 표시하지 않습니다. 선 위에는 서버의 `label`을 표시하고, 한 쌍에 참조와 공통 주제가 함께 있으면 "보안 참조"처럼 합칩니다. 레이아웃은 힘 기반 배치 대신 유형을 돌아가며 섞은 해바라기 나선형이고, 노드는 끌어서 옮길 수 있고, 옮긴 노드는 그래프를 다시 만들어도(새 답변·필터 변경·업로드) 그 자리를 유지합니다. 옮기지 않은 노드는 매번 배치를 새로 계산해 서로 겹치지 않게 합니다. 계산된 배치 위에 두 가지 보정을 추가로 거칩니다 — 근거로 커진 노드끼리 겹치면 떨어뜨리고(`separateEvidenceNodes`), 연결선이 관계없는 다른 노드를 그대로 지나가면 옆으로 밀어냅니다(`avoidEdgeNodeCrossings`). 두 보정 모두 사용자가 끌어서 옮긴 노드는 건드리지 않습니다(`positionOverrides`로 넘긴 노드는 고정). `DocumentLink` 형태는 이제 서버 응답 기준이라 더는 임시가 아닙니다. 화면 맞춤(sigma `autoRescale`)은 그래프를 새로 불러올 때 한 번만 하므로, 노드를 멀리 끌어도 전체 배율이 바뀌지 않습니다. 확대는 최대 10배, 축소는 최대 3배로 제한합니다.
- **그래프 시각 효과**(`widgets/document-graph/ui/SigmaCanvas.tsx`): 간선이 많으면 서로 겹쳐 엉켜 보이는 문제가 있어, 문서마다 가장 중요한 선(`markPrimaryEdges`, 경고>충돌>주제>참조 순) 하나만 기본으로 보여줍니다(`visibleEdge`). 노드를 고르면(클릭) 그 노드의 선만 모두 보이고 다른 대표 선은 흐려지며, 아직 고르지 않았을 때는 마우스를 올린 노드의 선이 모두 보입니다. 충돌·경고 선은 항상 글자까지 보입니다(`alwaysLabeled`). 그래프 탭을 처음 열 때는 노드·간선이 작고 투명하게 시작해 제 크기·색으로 커지는 등장 애니메이션이 한 번 재생되고, 노드마다 자기 색으로 번지는 그림자(backdrop)를 줘 입체감을 더했습니다. 노드를 끌 때는 마우스 이동의 일부만 반영해(`dragPositionToAttributes`) 체감 민감도를 낮췄습니다. sigma의 `nodeReducer`/`edgeReducer`는 `SigmaOptions` 최상위 속성이라 `settings` 객체 안에 두면 조용히 무시되니 주의합니다(실제로 한 번 이 실수로 전체 기능이 죽어 있었습니다).
- **그래프 근거 강조**: 답변에 근거가 있으면 근거 노드만 `highlighted`로 표시해 더 크게·라벨이 항상 보이게 둡니다(`widgets/document-graph/lib/buildGraph.ts`). 근거 외 노드·선을 흐리게 가라앉히던 "근거 포커스"(`FocusLevel`/`applyEvidenceFocus`, 왼쪽 아래 토글 포함)는 팀 요청으로 제거했습니다 — 위 선 표시 로직(질문 근거 잇기·호버·선택)과 책임이 겹치고 혼란을 줘서입니다. 채팅 패널의 "관계 그래프" 토글(`graphHighlightEnabled`)은 그대로 남아 있고, 근거 문서 ID를 그래프에 넘길지만 결정합니다.
- **문서 유형 표시명·색**: 서버 enum 5종(`HANDOVER`/`APPROVAL`/`REPORT`/`PRESENTATION`/`ETC`)에 한글 표시명을 고정 매핑했습니다(`entities/document/model/typeDisplay.ts`). 색은 원래 디자인(Figma "02 답변 · 관계 그래프 + 근거")의 다색 배색 대신, 다크 테마 그래프의 글로우 톤에 맞춰 파란 계열 단색 램프(명도·채도로만 유형 구분)로 바꿨습니다. 디자인팀과 정식으로 합의된 변경은 아니라 확인이 필요합니다.
- **그래프 탭 필터**: 문서 유형/확장자/작성 기간/부서·작성자 필터를 그래프 표시 범위에 적용합니다(`features/filter-documents`). 작성자는 서버에 필터 파라미터가 없어 클라이언트에서 부분 일치로만 거릅니다. 필터 드롭다운은 한 번에 하나만 열리며, 다른 드롭다운을 열면 이전에 열려 있던 드롭다운은 닫힙니다. 드롭다운 바깥을 누르거나 Escape를 눌러도 닫힙니다.
- **질문 검색 필터 연동**: 서버에 생긴 질문 API `filters`(`Trace-Server` PR #48)를 홈 화면·채팅 질문 전송에 그대로 실어 보냅니다(`features/filter-documents`의 `toQuestionFilters`). `sourceKinds`는 그래프 표시에는 못 쓰지만(문서 목록에 소스 종류가 없음) 질문 검색에는 보낼 수 있어 홈 화면의 "전체 문서함" 버튼에만 둡니다. 홈 화면의 "전체 문서함"과 "필터" 드롭다운도 동시에 하나만 열립니다. AI 서버가 실제로 필터를 적용하는지는 서버 문서(`ai-server-contract.md`)에도 아직 미확정이라고 적혀 있습니다.
- **홈 화면 제거(2026-11-06)**: 대화가 없을 때 보여 주던 홈 화면(`widgets/home-composer`)을 없애고, 처음부터 그래프와 채팅 화면을 보여 줍니다. 홈 화면에만 있던 "전체 문서함"(소스 종류) 질문 필터는 지금 화면에서 고를 수 없습니다(`SourceKindDropdown`, `FilterPanel`은 남겨 둠).
- **대화 기록**: 지난 대화 목록은 사이드바의 "최근 질문"에서만 보여줍니다(채팅 패널 위의 "대화 기록" 화면은 없앴습니다). 같은 대화 목록 API로 내 대화를 최근 갱신순으로 전부 보여주고, 길어지면 목록 안에서 스크롤합니다. 예전 "대화 기록" 화면에 있던 제목 검색과 날짜별 묶음은 함께 없앴고, 사이드바에 다시 둘지는 디자인 확인이 필요합니다. 대화 목록 API에 페이지 나눔이 없어 대화가 아주 많아지면 서버 쪽 페이지 API가 필요할 수 있습니다. 고르면 그 대화를 다시 불러옵니다(`entities/conversation`, `entities/evidence`, `features/conversation-history`). 메시지의 `evidenceChunkIds`는 근거 조회 API(`GET /api/evidence/{chunkId}`)로 하나씩 조회해 문서 제목 등을 채웁니다. 문서 삭제·개정·권한 변경으로 404가 난 근거만 빼고, 저장된 답변은 그대로 보여주며 "근거 N개는 표시할 수 없습니다"라고 알립니다. 연결 끊김·시간 초과·5xx처럼 일시적인 오류가 나면 근거를 빼지 않고 대화 열기를 실패로 알려 다시 시도하게 합니다. 대화를 연달아 고르면 마지막에 고른 대화만 반영합니다. 새 대화가 생기거나 답변이 추가되면 목록을 다시 받아옵니다.
- **대화 삭제**: 사이드바 "최근 질문"의 각 대화에 마우스를 올리거나 키보드로 초점을 옮기면 휴지통 버튼이 보이고, 확인 모달에서 "삭제"를 눌러야 `DELETE /api/conversations/{id}`로 지웁니다(`features/conversation-history`의 `DeleteConversationButton`). 서버는 대화와 메시지를 되돌릴 수 없게 지우므로 한 번 더 묻습니다. 지운 대화는 목록에서 바로 빼고 목록을 다시 받아옵니다. 지금 채팅에 열려 있던 대화를 지우면 지워진 대화에 이어서 질문하지 않도록 새 대화로 돌립니다(어느 대화가 열려 있는지는 위젯이 판단). 답변을 기다리는 중이거나 다른 대화를 여는 중에는 삭제 버튼을 막습니다. 서버에 일괄 삭제 API가 없어 "전체 삭제"는 두지 않았습니다.
- **지원 화면**: 2026-11-05 결정으로 모바일은 지원하지 않고 데스크톱·노트북 브라우저만 지원합니다. 노트북 화면(1280×720, 1366×657 등 브라우저 표시 영역 기준)에서 홈 입력창·전송 버튼, 필터 패널, 문서 탭이 잘리지 않는 것을 기준으로 맞췄습니다.

### 보류

- **답변 상태 구분**(찾을 수 없음, 검색이 필요 없는 질문): 서버·AI에 해당 응답 값이 정해지면 따릅니다. 지금은 `route`, `fallbackReason` 등을 해석하지 않고 답변 문장과 근거만 보여주며, 답변 문장은 가리지 않습니다. 근거가 0개이고 답변이 AI 서버의 고정 거절 문장일 때만 아래에 "필터 해제하고 다시 찾기"와 "다른 표현으로 질문" 버튼을 덧붙이고, 인사 답변과 되묻는 문장에는 붙이지 않습니다. 임시 판별이며 `Trace-Server` #82가 머지되면 `answerType`으로 바꿉니다.
- **원문 안 근거 하이라이트**: 서버가 주는 `charStart`/`charEnd`는 청크 텍스트 기준이고 화면 글자(Markdown 렌더 결과, PDF 텍스트 레이어)와 위치가 맞지 않아 쓰지 않습니다. 대신 양쪽을 NFKC로 맞추고 글자·숫자만 남겨(공백, 문장부호, Markdown 기호 무시) 비교해 위치를 찾고(`entities/evidence/lib/locate.ts`), CSS Custom Highlight API로 칠해 원문 DOM을 바꾸지 않습니다. 이 API가 없는 브라우저(Firefox 140 미만 등)에서는 칠하지 않고 위치 이동만 합니다. 근거 버전과 지금 원문 버전이 다르거나 PDF 글자 추출 결과가 달라 못 찾으면 바에 알리고, PDF는 근거 쪽 번호가 있으면 그 페이지로 이동합니다.
- **답변 문장 단위 인용**: 디자인은 답변 문장 안에 근거 번호를 바로 붙이는데, `AnswerSource`에는 답변 텍스트 안에서의 위치가 없어(청크 안 위치만 있음) 구현할 수 없습니다. 지금처럼 답변 아래에 출처 목록으로만 보여줍니다.
- **디자인의 8개 문서 유형(규정/매뉴얼/회의록 포함)**: Figma 목업은 서버 enum에 없는 유형까지 가정하고 있습니다. 분류 체계가 서버 enum을 포함해 넓어지기 전까지는 실제 5종만 씁니다.
- **문서 폐지/이전 버전 표시**: 디자인에 있는 "(폐지)" 마커는 문서 간 관계(버전 승계)를 나타내는 서버 데이터가 없어 구현하지 않았습니다. 엣지 API(#22)와 함께 정해질 것 같습니다.
- **그래프의 소스(문서함)별 필터**: `sourceKind`는 질문 검색 필터로는 쓸 수 있지만, `GET /api/documents` 응답에는 문서별 소스 종류가 없어(소스 ID만 있음) 그래프 표시를 소스별로 거르지는 못합니다. 문서 목록에 `sourceKind`(또는 소스 종류를 바로 알 수 있는 값)가 추가되면 그래프 필터 바의 "소스" 버튼도 켤 수 있습니다. 연결된 소스 이름(어떤 Notion/Obsidian인지)까지 보여주려면 일반 사용자가 쓸 수 있는 소스 조회 API(지금은 `GET /api/admin/sources`만 있어 관리자 전용)가 따로 필요합니다.
- **관리자 기능 중 문서 관리 외의 것**(사용자·부서·Notion 토큰 같은 시스템 관리): 서버 API가 없어 만들지 않았습니다. 문서 관리 화면은 [문서 관리 화면](admin-documents.md)에 정리했습니다.
- **알림**(문서 변경 시 위험도): 서버 API(#25)와 위험도 기준이 없습니다.
- **최대 문서 탭 수**: 임시로 10개입니다. 넘치면 가장 오래 안 본 탭을 닫습니다.
- **미리보기 탭 방식**, **새 질문 시 열린 문서 탭 처리**: 기획서에서 미결정입니다.
- **배포 방식**: 정적 파일을 서버 레포의 nginx에서 제공할지, 별도로 배포할지 미정입니다.
